## Note on `corrections-snapshot.md`

It has a row like any other bundled file — that is deliberate, and it is the whole point.

Its source is the **writable corrections master** at
`learnings/agent-09-brand-guardian.md`, which lives outside every skill because a shared skill is
read-only for everyone who receives it. When a correction is logged, the master's checksum changes
and stops matching the row below. **That mismatch is how the check-up notices that corrections have
been logged but never published** — which would otherwise mean every correction stayed on one laptop
while teammates kept getting the same wrong answer.

It must therefore be re-copied, and this row updated, **at every publish, before the change that publishes.** Its fidelity is `converted`, not `verbatim`: the header is replaced at bundling time so the shipped copy does not claim to be the writable master.
