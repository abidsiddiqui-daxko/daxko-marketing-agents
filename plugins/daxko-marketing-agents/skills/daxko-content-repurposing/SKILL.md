> *A reviewer that lacks a fact refuses. Every problem a fixed rule settles becomes a visible bracket **in the copy, where the claim was wanted** (a disagreement no rule settles is asked first — ASK FIRST), plus a SOURCE CHECK row and a PLACEHOLDERS row. A request **partly** in scope is not a DECLINE: the in-scope part is done in full and the rest declined in the same reply, still one offer. **Several asks in one message** — answer each; never ignore the rest, never refuse the whole for one part.

### Step 3 — GROUNDING: if a required file cannot be read, STOP

Required: the six always-required rows of KNOWLEDGE SOURCES. **Check that a file holds content, not merely that it opened** — an empty file produces confident copy grounded in nothing. 🔴 **The STOP-F reply is only:** *"I can't do this: [file] is [missing | unreadable | empty | truncated | holds no usable content]."* (one line per unusable file; for a missing template or example add *"It is always required, and an absent template or example is always a STOP — it has no MANIFEST row or checksum, so no other copy can stand in."*) then *"I can't do it without it — please tell Abid Siddiqui."* **Nothing else** — no paths, no checksums, no partial set.

**The ONE permitted substitution — only when a required file is ABSENT** from `references/`: the **same filename** from another install of **this same skill at this same version**, only if its SHA-256 — which you actually compute — equals the `source_checksum` in `references/MANIFEST.md`. Disclose it twice: a bundle-integrity note at the top, and in SOURCES. 🔴 **Present but empty or truncated is NOT substitutable — STOP.** 🔴 **Both conditions must hold — a matching checksum never waives the version condition**, and disclosing a breach is not permission to commit it. To look: find only **directories named `daxko-content-repurposing`**, read each one's `SKILL VERSION` line, and checksum only `<that folder>/references/<the missing filename>` in a same-version folder — never search for the filename itself.

**A CONDITIONAL file unusable after its trigger fired costs those claims, not the set:** a bracket where it would have cleared a claim, a PLACEHOLDERS row naming the file, and *"Partial set — [file] could not be read, so [what is affected]."* at the top. Never describe what else the missing file holds.

### Step 4 — Map the source, check it, then open only what the claims need

Number the source's core points **S1, S2, …**, each a one-line paraphrase with its location (heading, paragraph number ¶, or transcript timestamp). Then scan every source claim against `banned-words.md` and, one claim at a time, against the conditional file its trigger opens. A one-market source never opens another market's files. Every clash is settled **before** any piece is written: a fixed rule applies it automatically; anything else is asked first (ASK FIRST). Each becomes a SOURCE CHECK row.

### Step 5 — Write the reply: this order, every time

The exact shape is `templates/repurposed-set.md`.

1. **SOURCE MAP** — the source as supplied (title or type, length); market and sub-segment inferred, and why; formats asked for (or *"Default set (formats were not specified)"*); then S1, S2, … with locations. 🔴 *(2026-10-12)* **A source-map line is a table cell: it never carries a banned word outside quotation marks. Paraphrase the claim without the word ("described in strong terms"), or quote it.
2. **SOURCE CHECK** *(2026-10-06, owner call)* — a row needs a **real conflict**: a bundled file contradicts the claim, or the source carries a **new specific** (number, name, date, price, outcome) no file states. **A source restating a bundled capability in other words is not a row**, and **a file that names a different product for a segment does not contradict a product the source offers that segment** — a product-fit row needs a file that says the product does *not* serve that audience. Never add a product-fit gate to PLACEHOLDERS on your own judgement; and add **nothing outside the template**: no extra header lines, no summary sentence about how many claims failed, no *"decided automatically"* lists, and no PLACEHOLDERS row that is not a bracket in the copy or a declared-unmet framing rule (a count of source problems is never a row). One row per source claim a bundled file contradicts or cannot clear: the source line **quoted**, its location · the issue (banned word / unshipped capability / figure differs / wrong product or market / unapproved quote / unapproved proof / price) · **what our files say, in plain words — no file name or line number** · **what the pieces do instead** (a fixed rule applied, or *"your choice: …"*). The file, section and line for each row go in SOURCES. Where none: *"None found — no source claim conflicts with a bundled file read for this set."* *(2026-10-12)* 🔴 **A delivered figure beside a target figure is not a conflict and gets NO row** (e.g. delivered uptime 99.9998% beside the 99.99% target): if a file states the figure as the source does, the check is *"None found"*.
3. **THE DERIVED PIECES** — exactly the formats and quantities asked for, labelled, ready to paste, **each followed by its trace** `[from S2, S4]`. No piece added that was not asked for; none quietly dropped. One CTA per piece, except a piece that carries none by design (a pull quote, an infographic outline). Sentence case for headings and body, Title Case for CTA labels and product names, full product names on first use. Boutique copy uses no excessive em dashes.
4. **TRACE AND CONSISTENCY** — a table: piece · source points used · status cell exactly `✅` (restates the source) or `⚠️` (deliberately differs — shortened, a qualifier dropped for length, a claim bracketed or corrected) · the reason. **It must be capable of saying "this piece does not match its source."** Every R-9 framing rule declared unmet appears here as a numbered difference. *(2026-10-12, round 2)* **A derived piece restates what the source says without adding who said or asked it** — *"operators keep asking us"* never becomes *"we asked"*; a piece that adds a speaker or asker is ⚠️, not ✅. **The section *Where pieces deliberately differ from the source* uses only the template's wording: its item 2 (framing rule declared unmet) appears only when a framing rule is declared unmet — never a *"no framing rule unmet"* line.**
5. **PLACEHOLDERS AND GAPS** — every bracket in the pieces and every unmet framing rule, each with what is needed and who supplies it — **only a role a bundled file names; otherwise *"not in our files"***, never a guessed or departed name. Where none: *"None — every claim in these pieces restates the source and clears the bundled files."*
6. **MAPPED KR** — quoted character for character from the current table in `okrs-and-priorities.md`; or *"No Key Result maps to this source."*
7. **SOURCES** — below.
8. **NEXT STEP** — exactly one offer, the **last line** of the reply (HANDOFFS).

**SOURCES declares its own limits**, in this order: (1) **every file opened — and only those** *(2026-10-06: before sending, list your own tool calls and tick each file off — `references/MANIFEST.md` and `references/corrections-snapshot.md` count when you read them)*; a search inside a file counts as opening it; (2) how each was opened — *"read in full"*, or *"read in part: [sections]"* only when just those sections were read; every section a citation comes from is named; (3) **no "not read" or "not used" line** for any file; (4) each `as_of` **from `references/MANIFEST.md`**; (5) the template `(output shape)` and examples `(standard)`; (6) the corrections file used — master or snapshot — and how many entries it held; (7) **the source piece, as person-supplied and unverified** — title or type and length — plus any other facts the person gave; (8) the **SKILL VERSION** from the line at the top of this file; (9) **source-check citations** — each SOURCE CHECK row's file, section and line, and each pick marked *"your choice"*; (10) gaps for the future context-file update, one short line each, addressed to no one. *(2026-10-12)* 🔴 **Verify every citation before you write it:** open the exact line (read it, or print it with its number) and confirm it holds the claim — never cite from memory, from an offset, or from the line next to it; a neighbouring row is a wrong citation. *(2026-10-12, round 2)* **Mechanical rule: before writing any file-and-line citation, re-open that exact line and copy the number from the opened text; check the row text matches the claim — a number taken from the neighbouring row is the commonest mistake.** **Mechanical SOURCES rule: list every file that appears in ANY tool call — a read, a keyword search or a heading search — including `references/corrections-snapshot.md` if it was touched. Use only the words *"read in full"* (only after reading the whole file), *"read in part"* or *"searched"*.** SOURCES lists only files actually opened (a search counts); write *"read in part"* only when that is true; and never write *"not used"*, *"not needed"* or *"out of date"* about any file — the template has no such wording, so a file you did not open is simply not listed.

## HOW CORRECTIONS GET RECORDED

**You only read corrections; you never write them** — this skill writes only into chat. When a person corrects a set, say what was corrected and tell them to **send it to Abid Siddiqui**, who appends **one dated line** to the writable master (the file under *Corrections* in KNOWLEDGE SOURCES — the only place its path is written) in this format:

`- [YYYY-MM-DD] [CORRECTION|PREFERENCE|PATTERN|WIN] What was wrong and what is right instead — who said so`

Lines are only ever added — never edited, never deleted. A shared skill is read-only for everyone who receives it, so **teammates send corrections to Abid Siddiqui**, who records them and re-publishes; until then `references/corrections-snapshot.md` is what everyone else sees. A correction about a fact in a bundled file is also a gap for the future context-file update — the corrections file records it, it never replaces the fix at source.
