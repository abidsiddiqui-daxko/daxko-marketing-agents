## Why this file lives HERE and not inside the skill

The writable master sits in `learnings/`, **outside every skill folder, on purpose.**

A skill that has been shared — installed as a plugin, uploaded to claude.ai, or zipped to a
teammate — is **read-only for everyone who receives it.** Nobody else's Claude can write into it. If
the corrections file lived inside the skill, every correction would either be lost or would be
overwritten at the next update.

So the arrangement is:

| Copy | Where | Who can write to it |
|---|---|---|
| **The writable master** | `learnings/agent-11-thought-leadership.md` | Abid Siddiqui's machine only |
| **The bundled snapshot** | `references/corrections-snapshot.md` — this file | Nobody. Generated. Refreshed **before the change that publishes** — before the commit, before the version bump, whichever comes first (non-negotiable 11) |

Teammates read this snapshot and so receive the accumulated learning. **Teammates cannot log
corrections themselves — they send them to Abid Siddiqui, who records them in the master and
re-publishes.**

If the master is missing when the skill runs — which is normal on any machine but the owner's — the
skill reads this file instead. If neither exists, the work continues anyway and says so in its
SOURCES block. **A missing corrections file never stops the work.** That is the difference between
this file, which is OPTIONAL, and the knowledge files, which are REQUIRED.

## What this agent is for, so a correction can be judged in context

Agent 11 — Thought Leadership & Long-Form drafts **one long-form authority asset per request** — a
whitepaper, an eBook manuscript, an industry / research report, or an executive thought-leadership
(byline) article — to establish Daxko as an industry authority. It locks the thesis and outline
first, then drafts the full manuscript from bundled Daxko knowledge. It does not write a set of
short assets, does not plan or gate a lead magnet, does not pick topics, does not repurpose an
existing piece, does not search-optimize, and does not design or format the file.

Its sharpest failure mode is **invention**, and the risk is the highest of any content agent in the
programme: a whitepaper or research report is the exact format where a fabricated statistic sounds
most authoritative. A made-up number in a social post looks like a claim; the same number under a
chart, in Daxko's voice, over a named executive's byline, looks like *evidence*. Corrections about
invented statistics, customer names, quotes, prices, dates or unreleased capabilities stated as
shipped are the most valuable entries this file can hold.

**One correction class worth anticipating:** a person telling the agent that a `[PLACEHOLDER]` it
inserted is in fact a known, sourced figure. That is a legitimate correction about a *source file* —
the figure belongs in `product-knowledge.md` or `competitive-intel.md` — and it belongs both in the
master **and** as an owner fix at source (non-negotiable 17). It is **not** a licence to relax the
no-invention rule and start writing unsourced numbers.
